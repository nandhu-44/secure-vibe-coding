# OWASP Top 10 for LLM Applications (2025): code-level controls

Category IDs and names are from the [OWASP Top 10 for LLM Applications 2025](https://genai.owasp.org/llm-top-10/) (OWASP Foundation, CC BY-SA 4.0). The control column is SecureVibe's own summary.

| ID | Risk | Controls in code |
|---|---|---|
| LLM01 | Prompt Injection | Assume it will happen. Authz in tools, least privilege, human approval, delimit untrusted content, egress allowlists |
| LLM02 | Sensitive Information Disclosure | Server-side keys, RAG ACL filtering, PII minimization, redacted logs, no secrets in prompts |
| LLM03 | Supply Chain | Pinned model revisions, safetensors, no `trust_remote_code` on unvetted repos, vetted SDKs/plugins/MCP servers |
| LLM04 | Data and Model Poisoning | Provenance for training/RAG data, ingestion validation, review of user-contributed content before indexing |
| LLM05 | Improper Output Handling | Encode/sanitize for the sink. Schema-validate. Never eval/exec/SQL raw output |
| LLM06 | Excessive Agency | Minimal tools and scopes, per-user credentials, approval for consequential actions, step limits |
| LLM07 | System Prompt Leakage | Nothing secret in system prompts. Authz is not in the prompt |
| LLM08 | Vector and Embedding Weaknesses | Tenant/ACL filters in vector queries, per-tenant namespaces, deletion propagation |
| LLM09 | Misinformation | Grounding with citations, confidence/abstain paths, human review for high-stakes output |
| LLM10 | Unbounded Consumption | Auth, rate limits, token budgets, `max_tokens`, input caps, timeouts, spend alerts |
